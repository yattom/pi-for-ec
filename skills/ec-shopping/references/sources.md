# 情報源の使い分け

## ECサイト（価格・在庫の一次情報）

| ソースID | サイト | 取得方法 | 備考 |
|---|---|---|---|
| `rakuten` | 楽天市場 | 公式API（要アプリID） | レビュー件数・平均点も取れる。店舗によって価格差が大きい |
| `yahoo` | Yahoo!ショッピング | 公式API（要アプリID） | ポイント還元込みの実質価格に注意 |
| `amazon` | Amazon.co.jp | サイト指定のWeb検索 | 出品者によって価格・保証が変わる。マーケットプレイスに注意 |
| `kakaku` | 価格.com | サイト指定のWeb検索 | 最安値と価格推移。実店舗より安い場合の理由（並行輸入等）を確認 |
| `yodobashi` | ヨドバシ.com | サイト指定のWeb検索 | ポイント10%が多い。実質価格の比較材料 |
| `biccamera` | ビックカメラ | サイト指定のWeb検索 | 同上 |
| `mercari` | メルカリ | サイト指定のWeb検索 | 中古前提。ユーザーが中古可と言った場合のみ |
| `monotaro` / `askul` | モノタロウ / LOHACO | サイト指定のWeb検索 | 消耗品・工具・日用品に強い |

価格を提示するときは、**どのソースのいつ時点の価格か**を必ず添える。

## 独立レビュー（判断材料）

| 種別 | サイト例 | 読み方 |
|---|---|---|
| 利用者レビュー | 価格.com クチコミ | 件数が多い不満は本物。星1〜2のレビューを重点的に読む |
| 専門メディア | Impress Watch、ITmedia、価格.comマガジン | 実測値があるか確認。スペック紹介だけの記事は根拠が弱い |
| 比較検証系 | mybest、the360.life（LDK） | 検証方法が書かれているか。ランキング上位=広告のことがある |
| 海外専門サイト | RTINGS、DPReview、Wirecutter、TechRadar | 実測データが豊富。日本と型番・仕様が違う場合があるので要確認 |
| コミュニティ | Reddit、個人ブログ、note | 長期使用の不満が出やすい。一件だけの意見は鵜呑みにしない |

### 記事の信頼度を見分ける観点

- 実機を使ったか、スペック表を書き写しただけか
- 数値（実測値・使用期間）があるか
- 欠点が書かれているか（欠点ゼロの記事は宣伝の可能性が高い）
- 「PR」「アフィリエイト」の表示、購入ボタンの多さ
- 記事の日付（型落ち品の記事を最新として扱わない）

## 使い分けの原則

1. **価格はECサイト、評価はEC外**。ECサイトのレビューは購入者に偏るため、
   独立メディア・コミュニティと突き合わせる。
2. **海外情報は日本仕様との差に注意**。型番の末尾、電圧、保証、技適など。
   `review_research` の海外要約は日本語で返るが、日本で買えるかは `ec_search` で確認する。
3. **一次情報を優先**。メーカーの製品ページ（仕様表）は `web_fetch` で直接確認できる。

## 取得のマナー

- 検索・取得はすべて pi の実行マシンから行う。過度な連打をしない
  （拡張側でホストごとに最小間隔を空け、robots.txt を尊重している）。
- スクレイピングに依存せず、公式APIが使えるサイトはAPIを使う。
- 取得したページの内容をそのまま大量に引用せず、要約と出典URLで示す。
